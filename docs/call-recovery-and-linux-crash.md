# Call recovery and Linux fullscreen

The Linux journal showed a stack overflow from `CallWindow` changing `WindowState` inside its own native property notification. The handler now coalesces and defers normalization to the UI dispatcher. Linux presentation now uses a borderless normal window covering the current monitor instead of requesting native fullscreen; Windows and macOS retain native fullscreen. Escape restores the previous geometry, decorations, state and panels. Headless interaction tests verify Linux never transitions to native fullscreen and restore normal/maximized windows; no real screen or input was captured during verification.

The bridge forwards LiveKit SDK reconnect/reconnected events and numeric disconnect reasons. The current bridge ABI is 6 and includes reconnect event kinds 8/9; rebuild the packaged bridge with the managed changes. The application keeps the current server call and elapsed clock during recovery. On a recoverable terminal media disconnect it cleans up outside callback threads, obtains a fresh server-authorized token and attempts reconnect up to five times with 1/2/4/8-second delays. Leaving/sign-out cancels pending recovery. Duplicate identities, explicit removal, room deletion and other non-recoverable reasons do not trigger automatic rejoin. Screen capture and remote-control consent are not resumed implicitly.

Capability negotiation survives transient data-send failures; failed input is discarded and consent revoked. Windows bounds and absolute input use the primary screen, matching the supported share policy. Linux Wayland monitor sharing uses the system RemoteDesktop/ScreenCast portal with keyboard and pointer permission, followed by explicit per-participant consent. Window shares remain view-only. There is no XWayland input bypass; see [screen-sharing.md](screen-sharing.md).

Tests `RecoverableDisconnect_RejoinsSameCallWithFreshTokenWithoutLeavingOrResumingScreen`, `LeavingDuringRecoveryCancelsThePendingTokenAndDoesNotRejoin`, `ServerRemoval_DoesNotAutomaticallyRejoinOrLeaveTheServerCall`, and `SdkReconnection_PreservesCallAndDoesNotCreateAnotherRoom` cover managed recovery. The native ABI lifecycle smoke test and full desktop suite ran on Linux. Opt-in two-client network tests did not run without test tokens; real Windows/macOS input and production media stability remain unverified.
