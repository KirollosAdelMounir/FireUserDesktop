# Call recovery and Linux fullscreen

The Linux journal showed a stack overflow from `CallWindow` changing `WindowState` inside its own native property notification. The handler now coalesces and defers normalization to the UI dispatcher. Fullscreen is still entered explicitly for a focused screen share; Escape restores the previous state and panels. Headless fullscreen interaction tests exercise the deferred behavior; no real screen or input was captured during verification.

The bridge forwards LiveKit SDK reconnect/reconnected events and numeric disconnect reasons. It retains ABI 3 signatures and adds event kinds 8/9; rebuild the packaged bridge with the managed changes. The application keeps the current server call and elapsed clock during recovery. On a recoverable terminal media disconnect it cleans up outside callback threads, obtains a fresh server-authorized token and attempts reconnect up to five times with 1/2/4/8-second delays. Leaving/sign-out cancels pending recovery. Duplicate identities, explicit removal, room deletion and other non-recoverable reasons do not trigger automatic rejoin. Screen capture and remote-control consent are not resumed implicitly.

Capability negotiation survives transient data-send failures; failed input is discarded and consent revoked. Windows bounds and absolute input use the primary screen, matching the supported share policy. Linux Wayland shares remain view-only hosts, with a visible explanation; native/web viewers can still request consent from a supported host. No Wayland input implementation or XWayland bypass was added.

Tests `RecoverableDisconnect_RejoinsSameCallWithFreshTokenWithoutLeavingOrResumingScreen`, `LeavingDuringRecoveryCancelsThePendingTokenAndDoesNotRejoin`, `ServerRemoval_DoesNotAutomaticallyRejoinOrLeaveTheServerCall`, and `SdkReconnection_PreservesCallAndDoesNotCreateAnotherRoom` cover managed recovery. The native ABI lifecycle smoke test and full desktop suite ran on Linux. Opt-in two-client network tests did not run without test tokens; real Windows/macOS input and production media stability remain unverified.
