# Desktop notifications and form interaction

Fire User Connect displays branded, non-activating top-level toasts even when the main window is minimized. At most three cards appear at the right center of the main window's monitor. Placement uses the screen working area plus a margin, accounting for a right-side taskbar. Cards follow the web client: a 14px rounded surface, orange left accent, avatar or notification badge, timestamp, separate dismiss button and three-pixel countdown. Entry lasts 240 ms and exit lasts 320 ms; the application reduced-motion preference and `FIREUSER_REDUCED_MOTION` disable it.

After six seconds, notifications are also submitted to the operating system. Windows sets `SuppressPopup` to retain history without a second banner. macOS requests passive/list delivery. Linux uses the desktop notification service with persistent/silent hints; banner suppression and retained history depend on the compositor's notification server and user preferences. The freedesktop protocol has no portable history-only delivery flag. OS permissions and history settings still apply.

The application notification center combines session-local chat/call notices with the authorized persistent workplace notification feed. It loads an initial snapshot, handles SignalR notifications/read-state events and recovers on reconnect. Earlier workplace items load on demand. Chat/call notices are not persisted locally after sign-out. Clicking a toast, OS notice or center item uses the same internal route: direct/group chat, incoming call, meeting, announcement, vacation or calendar. A workplace notice is fetched and marked read through the authenticated API. Resources without a dedicated desktop management view retain the notification's title/body; this is not full Angular feature parity.

Conversation history loads once per visited conversation, merges concurrent live arrivals, and caches previous conversations for this login session. Incoming messages, edits, deletions and read receipts update that state. Reconnection clears cached snapshots and recovers the active conversation. Read receipts use the server's through timestamp and a single sent check/double seen check. The backend history endpoint now emits the same timestamped receipt as the chat hub, addressed to the original sender.

Upload/recording activities use Angular's `NotifyChatActivity` contract with three-second lease renewal and expiry. Voice recording starts only from the explicit microphone button, uses native mono 48 kHz PCM capture and encodes AAC at 128 kbps into an M4A (`audio/mp4`) file with the packaged FFmpeg runtime before encrypted upload. Raw PCM is temporary and never uploaded. Switching conversations or signing out stops an active recording. Recording files remain temporary and are deleted during cleanup. No microphone is opened by device discovery or tests.

Enter submits text forms; Shift+Enter inserts a new line in multiline fields. Calendar Enter first reviews the exact draft and saves on a subsequent Enter, preserving conflict acknowledgement. Changed drafts are reviewed again. Vacation Enter previews shifts/balances before submission. Login, meeting codes, announcements, chat unlock and call/profile message inputs use their respective submit commands. Dropdown selection and modified shortcuts remain native.

Calendar tabs are Calendar, Vacation and Organization Calendar. User selection is limited to the current user and positive reporting-distance descendants. Shared organization/unit choices come only from the server's authorized shared-calendar scope. Server permissions remain authoritative.

Calls show a connecting window while token retrieval/native connection is pending. Meeting joining retains explicit invitation review and server attendance/start policy, then watches the meeting hub with liveness heartbeats. End/cancellation events leave the room. Declined/unauthorized invitations are not bypassed.

The existing CMake bridge remains independently buildable through the native scripts, called automatically by managed builds and bundled by the publish scripts. Build on each target OS/architecture; binaries cannot be validated for all three systems by Windows cross-publishing. Windows executable metadata now identifies the product and file description as Fire User Connect.

Windows managed builds resolve PowerShell by absolute path, preferring an installed PowerShell 7 and falling back to Windows PowerShell with its own built-in module directory. IDE builds therefore do not depend on `pwsh` being present in the IDE's inherited PATH. `PowerShellExe` remains overridable.

Direct CMake/VS Code configuration first honors an explicitly configured LiveKit SDK, then discovers the matching pinned SDK under `Native/sdk/<rid>`. A fresh checkout still needs the native build script once to download and verify dependencies. Windows native Debug builds retain debug symbols while matching the prebuilt SDK's Release CRT/STL ABI; SDK DLLs are copied beside the native output for debugging.

## Page motion and shutdown

TabControl's built-in outgoing-page transition is disabled to prevent two live pages overlapping. Main tabs, conversation detail tabs and screen-picker tabs animate only the incoming content, with stale queued entries cancelled on rapid selection. Calendar/Vacation/Organization Calendar also animate their shared content on selection and move the orange selection indicator in 240 ms with the frontend navigation curve. Network requests start normally without waiting for animation. Dialogs, profile overlays, editor drawers and context menus have short entry motion; dialogs and overlays retain their surfaces through exit. Reduced motion bypasses surface and selection animation.

System shutdown and external application quit requests are never cancelled by the close-to-tray policy or by cleanup. Explicit tray Exit allows three seconds for cleanup before closing. System shutdown is best effort and does not wait for backend operations. Main and call windows allow OS/application/owner shutdown through. Windows single-instance IPC cancellation interrupts both an idle listener and a connected client's pending read; token sources are released after the listener completes, and running tasks are never disposed.

Windows headless tests cover rapid sub-tab changes, cancellation/restoration, close-versus-open toast actions, pending shutdown cleanup and idle/connected IPC disposal. Actual OS shutdown, macOS and Linux native session termination require target-platform validation.

## Voice notes and inline audio

The composer follows the web voice-note flow: opening/recording/preparing/ready states, an elapsed recording timer, stop/discard, preview, and a voice-only send. Text drafts are retained while the voice composer is active. Voice notes cannot start alongside an edit or selected file attachments. Failed sends retain the recording for retry; conversation changes and sign-out invalidate pending microphone/encoder work and delete temporary captures.

Audio attachments (including older WAV notes and web M4A/Opus notes) render an inline native player with play/pause, seek and elapsed/total time in both the main conversation and call chat. Playback is explicit. Attachments use the existing authenticated/decrypting download path into temporary owner-only files; playback does not launch an external application or open a save dialog. The packaged decoder supplies paced PCM to native miniaudio output. Pause, detach, source changes, discard and sign-out stop playback and clean up owned temporary files. New encrypted metadata preserves the MIME type instead of marking every attachment as application/octet-stream.

Angular requests `audio: true` and prefers audio/mp4 when supported, falling back to browser Opus containers; it sets no fixed voice-note bitrate or sample rate. Desktop consistently uses AAC/M4A at the native settings above. Browser-provided echo cancellation/automatic gain processing and web playback receipts are not implemented by this change. Tests encode/decode only synthetic PCM and never open a microphone or speaker. Windows runtime validation does not verify physical audio devices or Linux/macOS playback.

### Angular voice-player design

Voice players now use the Angular 310px capsule, 20px corners, white circular play button, 48 rounded waveform bars, played-progress highlighting, compact speed button and timer pill. Sent notes and previews use the primary gradient; received notes use the themed card surface and text color. The recording composer uses a single pill-shaped row: discard icon, microphone/status, stop icon while recording, and waveform preview/send when ready. Keyboard focus and seeking remain accessible and reduced-motion users receive no decorative animation.

Playback cycles 1× → 1.5× → 2× → 0.5× → 1×. FFmpeg's atempo changes speed without changing pitch; seeking/progress stay in original clip time and changing speed preserves the current position. Waveforms are measured from decoded PCM, never decorative/random bars. The existing Angular optional encrypted `waveform` metadata is read and written so either client can render peaks before playback. Analysis is streamed into 48 peak buckets with bounded memory; files over Angular's 32 MB analysis threshold still upload and play normally, with a neutral track when peaks are unavailable. No attachment size cap is introduced.
